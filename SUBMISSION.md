## Финальные команды Git — выполняет пользователь

Запускать в исходном Git-репозитории, не в распакованном ZIP. Рабочее дерево
должно быть чистым. На момент подготовки локальной `main` нет.
Все feature-ветки образуют цепочку, поэтому финальная включает все предыдущие.

```sh
git status --short
git switch -c main feature/dsu
git merge --ff-only feature/metrics-final
git tag -a v1.0 -m "DAA Assignment 3 v1.0"
git push -u origin main
git push origin v1.0
```

Если вы уже создали `main`, вместо `git switch -c main feature/dsu` выполните
`git switch main`. Не применяйте force при ошибке fast-forward: сначала проверьте
новые коммиты. Порядок включения кода:
`dsu -> mst -> scc -> paths -> metrics -> scc-tarjan -> paths-critical -> metrics-final`.
Одно финальное fast-forward-слияние сохраняет все эти коммиты без переписывания.

После замены личных данных нужно сохранить их коммитом на `main` **до создания
тега**, затем пересобрать архив. Если изменения внесены после подготовки текущего
ZIP, старый ZIP не содержит их.

## Архив

Архив с явными placeholders создаётся командой:

```sh
python3 scripts/package_submission.py
```

Файл: `dist/DAA_Assignment3_NAME_SURNAME_GROUP.zip`.
Перед сдачей используйте настоящие данные:

```sh
python3 scripts/package_submission.py --name NAME --surname SURNAME --group GROUP
```

Скрипт берёт отслеживаемые Git-файлы из текущего рабочего дерева, включая исходники,
тесты, данные, CSV, PNG, отчёт и инструкции. `target/`, `.git/`, временные файлы
и предыдущие архивы не включаются. ZIP проверяется на целостность после создания.
По PDF архив загружается в Moodle, а ссылка должна вести на репозиторий с `main`
и тегом `v1.0`.
